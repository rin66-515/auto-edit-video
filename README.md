# 本地 Vlog 自动化工作流

把每一期素材放入 `D:\vlog\inbox\项目名`。文件稳定5分钟后自动开始；如果想立即开始，可以在项目目录建立空文件 `READY.txt`。

浏览器审核地址：<http://127.0.0.1:4380>

## 能力

- 素材入库、ffprobe 技术分析、代理视频、音频抽取和缩略图
- 中文/日文语音识别与时间轴接口（Qwen3-ASR）
- 镜头和故事结构分析接口（Qwen3-VL）
- 长篇 16:9 与短篇 9:16 的独立版本、审核意见、锁定和重新渲染
- 四个平台上传完成确认
- AI分析完成后自动排队生成长篇和短篇，无需手动点击请求渲染
- 默认双风格：YouTube/Bilibili 为10–60分钟日系生活长篇，抖音/小红书为30–90秒强钩子网感短篇
- 默认只保留本人清晰，使用本地 YuNet + SFace 检测/比对，并以指定头像贴纸遮挡其他真实人脸；身份模型、本人参考照片或遮挡头像缺失时拒绝输出未处理成片
- 四平台全部确认时立即删除临时渲染缓存；原片、代理、音频、缩略图等中间文件保留14天，已批准成片从“批准/四平台确认”较晚时间起保留90天
- 每个平台都可再次点击取消确认；14天内取消会撤销中间文件清理倒计时，重新完成四项确认后重新计时
- SQLite 元数据、字幕、审核意见和日志长期保留

## 启动

```powershell
cd D:\vlog\_automation\repository
docker compose up -d
```

浏览器打开 `http://127.0.0.1:4380`。代码位于本目录；视频和模型只保存在 `D:\vlog\_automation`。系统不会扫描 `D:\vlog` 下已有的其他文件夹。

## 按需启动和停止

Vlog服务不会随Docker自动运行。需要使用时执行：

```powershell
& "D:\vlog\_automation\repository\scripts\start.ps1"
```

结束后执行：

```powershell
& "D:\vlog\_automation\repository\scripts\stop.ps1"
```

停止脚本只关闭Vlog服务，不影响其他Docker项目。

日常启动不再自动重建大型 CUDA 镜像；应用代码通过只读目录挂载生效，避免每次修改页面或工作流都产生大量 Docker 临时空间。只有首次迁移到新服务器，或 Dockerfile/依赖发生变化时，才需要运行 `docker compose build`。

`scripts\start.ps1` 会明确启动审核页、音频、语音识别和画面分析四个服务，并等待三个工作器心跳上线。审核页会显示工作器在线状态；当前阶段需要的工作器离线时，“启动/继续”会被禁用，接口也会拒绝进入假运行状态。

审核页内的“停止”只停止所选项目任务，审核网页仍可使用；`scripts\stop.ps1` 才会关闭整套 Vlog 容器。

## 人脸隐私

- 长篇和短篇默认设置为 `cover_non_owner_faces=true`（同时兼容旧键 `blur_non_owner_faces`）：仅本人保持清晰，除本人外的主要登场人物在字幕、音乐和画面合成后使用 `identity/privacy-avatar.jpg` 头像贴纸遮挡；远景、背景路人默认不处理。只有项目设置或人工时间码明确豁免时，其他主要人物才保持清晰。
- 遮挡轨迹默认提前 5 帧、延后 5 帧；只有连续检测且具有人脸画面变化的轨迹才遮挡，静止雕像、模型和一次性误检会跳过。
- 本人参考照片保存在 `D:\vlog\_automation\identity\owner`，人脸模型保存在 `D:\vlog\_automation\models\opencv-face`，两者都不放入 Git。
- 迁移服务器时必须通过私密方式单独复制上述两个目录；缺少任一目录时，系统会让渲染失败并写入日志，不会降级输出未打码视频。
- 特殊项目如不需要打码，应在项目设置中显式设定 `privacy.blur_non_owner_faces=false`；不得把本人参考照片加入公开仓库。

## 项目控制与日志

- 新素材扫描和代理文件生成结束后，项目停在“等待启动”，不会直接进入 AI 处理。
- “启动项目”从第一个待处理阶段开始；“暂停”在当前素材结束后保存检查点；“继续”跳过已完成素材；“停止”保留结果并等待下次启动。
- “运行日志”每 60 秒自动刷新，也可点击“立即刷新”；记录阶段开始/完成、当前素材、安全暂停/停止位置、降噪降级警告和捕获到的异常详情。剪辑方案生成、成片渲染和隐私打码等长耗时阶段每 10 分钟写入一次运行心跳，便于确认任务没有卡住。
- 成片渲染固定显示汇总进度 `长篇 0/1｜短篇 0/N`；每个长篇或短篇开始、完成、失败以及每10分钟心跳都会更新计数，便于直接判断还剩几个文件。
- 剪辑方案生成采用“AI紧凑创意结构 + 程序确定性时间线”：AI只决定故事锚点、章节、素材优先级和短篇主题，程序再按真实素材时长生成并校验全部区间。生成前显示预计 `1 长 + 1–3 短（共 2–4 个成片）`，通过后记录确定的长短篇及文件总数；AI JSON 即使解析失败也会自动使用确定性故事结构，不再对被截断的长时间线连续盲目重试。
- “素材与代理预览”只用于查看原素材分析与代理画面；最终字幕审核已统一放到“历史版本与成片审核”，避免原素材时间轴和成片时间轴混淆。
- 每个母版版本可导出 XLSX 审核表，在 Excel 中修改开始时间、结束时间、中日字幕、保留/省略和“需复核”。导回时系统按隐藏校验 ID 整批核对，拒绝缺行、重复行、越界时间和只读字段篡改；修改结果绑定当前成片时间线，并在字幕烧录时使用新的时间节点。
- 母版生成后项目自动停止。字幕与时间节点可以反复导出、校对和导回，不会重新剪辑视频；确认无误后锁定字幕并快速生成烧录版。母版本身不满意时，可废弃该母版并按保留的版本设置重新渲染。
- 项目发生失败时会自动停止；修复问题后可从页面再次启动，按日志中的检查点继续。
- 各工作器只恢复自己负责的中断阶段：重启审核网站不会误暂停仍在线的音频、转写或画面任务；工作器自身重启时则安全回到该阶段检查点。
- 有效长篇和短篇都“批准锁定”且项目停止后，可点击“审核完成并立即删除原片”。系统只删除该项目 `inbox` 内经过路径校验的原始视频，代理、字幕和成片继续保留；此操作不可撤销。
- “请求成片与历史版本”中的每个版本可单独删除；点击“删除历史版本”会弹出包含版本号、画幅和状态的二次确认。项目必须先暂停或停止，正在渲染的版本不能删除；删除只影响该版本记录、成片和双语字幕文件。
- 四个平台全部确认后，系统立即清理该项目的失败/中断渲染缓存并开始14天倒计时；到期后自动清理原片、代理、原始及增强音频、缩略图和画面采样。批准成片满90天后自动删除成片及其双语字幕文件，并在运行日志中记录释放空间。
- 14天内取消任一平台确认会清空倒计时；已经执行过的清理不可恢复。服务关机期间错过期限时，下次启动会自动补执行。

## D 盘保护

- D 盘低于 `MIN_FREE_GIB`（默认 80 GiB）时，页面会阻止启动、继续和新渲染，并把原因写入项目日志。
- 原片、模型、代理、音频和成片不属于缓存，不会被缓存清理误删。
- Docker 构建缓存可以使用 `docker builder prune --force` 清理；虚拟磁盘文件清理后不会自动缩小，需要在 Docker Desktop 完全停止时单独压缩 VHDX。
- AI模型和Vlog工作镜像是跨项目共用资源，不随单个项目的四平台确认删除，以免下一期重新下载和构建几十GB内容。
